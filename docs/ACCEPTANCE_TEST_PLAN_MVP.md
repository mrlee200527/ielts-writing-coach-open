# 雅思作文助手 MVP 第一版验收测试计划

- 状态：第一版，待程序员实现后执行
- 日期：2026-08-13（北京时间）
- 测试角色：测试 AI
- 依据：`docs/PRODUCT_REQUIREMENTS_MVP.md`、`docs/ARCHITECTURE.md`
- 范围：IELTS Academic Writing Task 1 MVP，不修改或放宽产品验收标准

## 1. 测试目标与质量结论

验证用户能在 AI 不稳定时仍完成“导题—写作—保存—提交—评分—学习档案—删除”主链路，并重点证明克制型干预、版本隔离、不确定性传播、证据门槛和删除一致性成立。

发布前必须满足：

1. 11 组 Acceptance Criteria 全部通过，无 P0/P1 缺陷；
2. stale revision、提交冻结、删除一致性不得存在已知失败；
3. AI 超时、无效输出和终态失败均不得阻断编辑、保存、读取已提交正文或删除；
4. 四类题图均进入人工标注回归集，不确定事实不会单独触发判错；
5. 所有关键断言可通过用户界面与只读测试观测共同取证。

## 2. 测试分层与方法

| 层级 | 工具/方法 | 主要责任 |
|---|---|---|
| 领域验收 | Vitest、伪时钟、内存/测试存储适配器 | 计时边界、状态机、哈希失效、预算、幂等、证据计数 |
| API/集成 | Vitest、固定 LLM/Job/Storage doubles | 事务、异步任务、失败降级、事件和投影一致性 |
| 用户流程 | Playwright | 11 组 AC 的可见行为、刷新恢复、提交与删除 |
| AI 回归 | Prompt fixtures、四类题图 golden dataset、人工复核 | Schema、事实引用、帮助边界、评分限制，不断言逐字一致 |

确定性规则必须使用固定输入得到精确结果；模型行为只校验结构、证据约束、禁止项和人工标注容差，不以文案逐字匹配作为通过条件。

## 3. 测试环境与数据

- `NODE_ENV=test`，启用只读 `TestObservationPort`；使用可注入 `Clock` 和可控任务调度器。
- LLM double 支持：成功、延迟、超时、网络失败、无效 JSON、Schema 不符、重复回调和晚到结果。
- 每类题图至少准备：清晰样本、不确定样本、完全不可用样本；覆盖动态、静态、流程图、地图。
- 作文夹具包含：149 词、150 词、151 词；同一问题跨 1/2/3 篇已完成作文；同类提示连续忽略；提交后继续产生草稿副本。
- 每个用例使用独立用户和会话；固定 Prompt、rubric、Task Context 版本并记录 fixture ID。

## 5. 关键验收用例

### AT-01 四类题目导入与处理中状态

**Given** 用户依次上传动态、静态、流程图和地图题图，可选填题目文字。
**When** 图片理解任务处于排队、运行和完成状态。
**Then** 处理中只展示原图与真实状态；不得显示未完成的推断；成功后均可进入空白工作台并看到原图和题目。
**证据** `task.context_ready`、对应 `task_context_version_id`、Playwright 截图。

### AT-02 题图不可用时降级

**Given** 图片理解连续失败或无法生成可用结构。
**When** 用户进入工作台并写作、保存、提交。
**Then** 显示通俗限制说明且无置信度数字；全主链路可用；相关评价输出限制而非虚构事实。
**证据** `task.context_degraded`、评分 `limitations`、无阻断 UI。

### AT-03 自动保存独立于 AI

**Given** AI Gateway 超时，用户持续输入。
**When** 自动保存完成并刷新页面。
**Then** 字数和用时即时更新；恢复最近成功 revision；仍可提交。
**证据** revision 单调递增、保存完成时间、`assessment/analysis` 故障记录。

### AT-04 句子三种触发及 1.5 秒边界

分别验证句末标点停顿、光标离句、换行后开始下一句。伪时钟推进到 1499 ms 时不得请求；推进至 1500 ms 且文本不变时仅请求一次。离句和开始下一句应立即形成请求，不额外等待。相同 `sentence_text_hash` 重放不得创建第二个分析任务。

### AT-05 句子帮助边界

**Given** 固定模型返回拼写与语法候选。
**Then** 拼写候选为 1–3 个且正文未被系统改写；默认语法提示只含位置、影响和规则方向；用户主动展开后只显示局部示例，不出现整句替写。

### AT-06 句子 stale revision 竞态

**Given** revision R1 的句子检查已运行。
**When** 返回前修改目标句形成 R2，再让 R1 成功晚到。
**Then** R1 标为 `STALE`，不展示、不占句子反馈槽、不写长期记忆；R2 可独立检查。修改无关句子但目标句及必要依赖不变时，结果不得被误判 stale。
**证据** `sentence.result_stale`、text/dependency hash、策略状态。

### AT-07 段落触发、短段门槛与 stale

自动触发在 2999 ms 不请求、3000 ms 请求一次；等待中修改目标段或边界则取消。空段、占位符或不足一个完整句时产生 `paragraph.check_skipped(reason=INCOMPLETE)`；点击“检查本段”须立即请求并绕过门槛。运行后改变段落文本、相邻摘要、Task Context 或 Memory 投影版本，旧结果必须 stale；最多展示两条且不得生成整段答案。

### AT-08 反馈预算、去重与抑制

1. 已有未处理句子反馈时，新候选只能延迟、观察或抑制，不得并列第二条；
2. 同一段返回三个高价值问题时只主动展示优先级最高两条；
3. 相同 `issue_key` 再次出现时不得重复主动展示；
4. 同一类别连续两次 `feedback.ignored` 后，第三次候选必须 `SUPPRESS`；
5. 刷新和重新进入后预算、忽略次数及抑制状态不丢失；
6. stale 候选不得消耗任何预算；不处理反馈不阻止继续写作和提交。

### AT-09 AI 超时、失败与重复任务

对句子、段落、题图、评分分别注入超时、网络失败、无效 JSON 和 Schema 不符。结构化输出首次失败最多执行一次修复调用；实时检查失败静默降级且不产生伪反馈；评分进入 `RETRYABLE_FAILED` 或 `TERMINAL_FAILED` 并显示可理解状态。相同幂等键重放只允许一个有效结果，晚到/重复结果不得覆盖新状态。

### AT-10 fact 级不确定性传播

**Given** Task Context 同时含 `CERTAIN`、`UNCERTAIN`、`UNAVAILABLE` facts。
**When** 候选判错只引用不确定 fact。
**Then** Intervention Policy 强制抑制判错型反馈。若另有独立确定事实和作文证据，可评价但必须保留引用链。评分页须显示受影响维度和限制，不显示内部置信度。四类题图分别验证数据标签、流程箭头和地图方位等类别。

### AT-11 少于 150 词提交

149 词点击提交后创建绑定当前 revision 的 intent，状态为 `AWAITING_WORD_COUNT_CONFIRMATION`，不启动评分。返回编辑后旧 intent 取消；正文改变再确认时必须拒绝旧 intent 并重新计数。未改正文确认后只冻结一次，记录提交字数和风险确认。150/151 词直接提交，不出现风险确认。

### AT-12 冻结版本与评分失败

**Given** 提交冻结 R10。
**When** 后续恢复、复制或编辑形成其他 revision，且 R10 首次评分失败后重试。
**Then** 所有评分始终绑定 R10、同一 Task Context/rubric/Prompt 版本；已提交正文始终可读；重复确认和重复任务不能产生第二个冻结版本或不同正文的评分。

### AT-13 全文评分内容约束

结果页必须显示带“非官方成绩”的 0.5 band 总分估计、四维分数；每维恰有 1 条正文证据支持的优点、最多 2 条主要问题；全文仅 1 个最优先改进项和 2–3 个具体练习；同时显示字数、用时、冻结正文与已展示反馈。不得出现伪精确概率、完整范文或写作阶段预测分数。

### AT-14 Student Memory 两篇证据门槛

同一 `skill_key` 在第一篇已完成作文产生有效证据后，不显示 `FREQUENT_ISSUE`；第二篇不同已完成作文产生证据后才可显示，并列出两个来源。相同作文的多个反馈只能按一篇计数；未提交、已删除、无效或实时分析证据不得计数。“下一篇重点”最多两项。

### AT-15 学习状态迁移与记录删除

用连续已完成作文构造频率下降和稳定表现，验证状态可迁移为“正在进步”或“已掌握”，不会永久停留为负面标签。删除学习记录后立即隐藏、停止个性化并写 tombstone；后台重算不得令其静默复活，作文和评分仍保留。

### AT-16 删除作文的一致性

**Given** 作文 E2 是某高频问题的第二篇证据且存在评分、反馈和运行中任务。
**When** 用户确认删除 E2。
**Then** 先进入 `DELETION_PENDING`，禁止新任务；历史、正文、反馈、评分和证据对用户不可见；晚到结果不进入投影；相关 Memory 进入 `RECOMPUTING` 且暂不用于个性化；完成后因仅余一篇证据而撤回高频问题。
**证据** `essay.deletion_started` → `memory.recompute_requested` → `essay.deleted`/`memory.recomputed`，来源列表无 E2。

### AT-17 删除后的保留、引用与幂等

删除一篇作文后若仍有至少两篇不同作文证据，高频问题应保留但来源、优先级和投影版本更新。重复 DELETE、重复 outbox 投递和重算重试不得重复撤销或破坏剩余数据。共享题图仍被其他任务引用时不得删除对象；无引用时按存储策略清理。

## 6. AI Golden Regression

Golden 集不要求模型措辞固定，但每次候选发布必须验证：

- 输出通过版本化 Zod Schema，所有 claim 引用存在的作文证据及 `supporting_fact_ids`；
- 不确定事实单独支撑的负面判断数量为 0；
- 拼写候选不超过 3，默认语法反馈无整句改写，段落反馈无整段答案；
- 每个评分维度的 band 为 0.5 步进，证据能定位到冻结正文；
- 四类题图的关键确定事实、未知类别和受限维度由人工标注者复核；
- Prompt、模型、rubric 和 fixture 版本随结果保存，失败样本可重放。

## 7. 程序员必须满足的可测性要求

1. **时间可控**：句子 1.5 秒、段落 3 秒、超时、重试和冷却全部依赖注入的 `Clock`/Scheduler；测试不得真实等待。
2. **异步可控**：`JobPort` 与 `LLMPort` 可暂停、释放、失败、重复和乱序完成，以稳定复现竞态。
3. **只读观测**：`TestObservationPort` 仅在测试环境启用，可按 correlation ID 查询领域事件、analysis 状态、策略状态、冻结 revision、assessment limitations、Memory 投影和 outbox；不得写领域状态。
4. **事件完整**：关键事件包含 event/aggregate/revision/segment/task-context ID、text/dependency hash、correlation/causation/idempotency key、时间和结构化 `reason_code`。
5. **状态显式**：取消、stale、deferred、suppressed、retryable failure、terminal failure、deletion pending、recomputing 不得用日志文本隐式表达。
6. **稳定身份**：句子、段落、issue、skill 和 fact 使用稳定 ID/key；stale 判定必须暴露参与比较的依赖版本或哈希。
7. **策略持久化**：活动句子反馈、每段计数、已展示 issue、忽略连续次数、类别抑制和版本可跨刷新查询。
8. **冻结可追溯**：提交 intent、风险确认、冻结 revision、提交字数、Task Context、Prompt 和 rubric 版本可关联查询；评分不能读取可变当前草稿。
9. **失败可注入**：每个外部端口均支持超时、无效结构、网络失败及部分成功；错误响应使用稳定错误码，UI 不依赖供应商原始文案。
10. **删除可审计**：删除事务、任务取消、证据撤销、outbox 和重算均幂等；测试能等待投影达到指定版本而非使用固定 sleep。
11. **隐私约束**：测试日志默认不输出全文、密钥或签名 URL；必要正文通过 fixture ID 和 hash 定位。
12. **选择器稳定**：关键 UI 元素提供语义角色或稳定 `data-testid`，至少覆盖原图、处理/保存/检查状态、反馈卡、风险确认、评分限制、Memory 来源和删除确认。

## 8. 缺陷等级与执行顺序

- **P0**：数据越权/丢失、删除后仍参与个性化、评分绑定错误正文、敏感信息泄露。
- **P1**：主链路阻断、stale 反馈展示、不确定事实单独判错、预算/两篇门槛失效、提交重复冻结。
- **P2**：单个降级状态或证据展示错误、有绕行方案的功能缺陷。
- **P3**：不影响规则与理解的视觉或文案问题。

执行顺序：领域状态机与竞态 → API/事务与失败注入 → Playwright 11 组 AC → 四类题图/评分 golden 回归 → 删除与全量回归。任何 P0/P1 出现时停止发布结论，修复后重跑所属 AC 及其上下游主链路。

## 9. 交接与待确认风险

- 交付程序员 AI：先实现确定性状态机、事件 Schema、测试端口和 fixtures，再连接真实 LLM；不得通过放宽断言适配不稳定实现。
- 交付架构 AI：评审事件 payload、删除事务/outbox 及 Memory 投影等待机制是否完整实现既定契约。
- 当前非阻塞风险：LLM 预算、区域和数据保留约束尚未确认；上线前需补充对应安全与成本验收阈值，但不影响本计划的功能验收执行。
